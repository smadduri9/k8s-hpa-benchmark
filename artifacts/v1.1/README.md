# Phase 5 public evidence — v1.1

This directory is a self-contained offline verification package. It contains 33
completed arms: six flash repetitions, two ramp repetitions, and one repetition
each of constant, WorldCup98 periodic and RetailRocket periodic. Each repetition
has fixed, tuned HPA and stock HPA arms. Completion is relative to that scope;
the original three-repetition scope for non-flash workloads was not completed.

From the repository root, with the repository virtualenv:

```bash
".venv/bin/python" -B artifacts/v1.1/verify.py
```

The verifier also runs with a standard-library Python interpreter after copying
this directory alone. It performs no network or cluster operations. The default
command writes nothing. `--write` deliberately regenerates summaries, the manifest
and checksums after an intentional evidence or policy change. It is not a way to
approve unreviewed input changes.

## Evidence and calculations

- `runs/`: byte-preserved measured Locust stats, replica series, timestamps and
  statuses. The full contaminated flash tuned rep-1 series is intentionally kept.
- `exclusions.csv`: executable metric-specific policy. Tuned rep-1 latency stays;
  its ready-pod time is excluded. Incomplete ramp rep-3 is not bundled.
- `metadata/completion.json`: sanitized completion-marker extracts, original log
  hashes and line numbers. Full logs remain private and are not verifier inputs.
- `metadata/runs.json`: declared configuration and measured repetition scope.
  Complete per-deployment hardware inventories and warm-up CPU comparison logs
  are `MISSING`. No hardware-causation claim is supported.
- `capacity/`: observed probe steps, their Locust stats, extracted CPU medians and
  compact derivation. Individual pod CPU readings are `MISSING`. The selected
  user amplitude is a model-derived calibration parameter, not a directly measured
  maximum capacity. Only one probe sweep is retained.
- `workloads/`: five selected aggregate one-second windows, provenance, top-five
  candidate tables and extraction summaries. Original event-level traces are not
  included. The verifier regenerates the normalized plateaus and peak-to-mean
  ratios. Candidate rankings and source Hurst values are retained context, not a
  rerun of the full selection search. Periodic source windows are compressed from
  24 hours into 18 minutes during load generation; the workload is a closed-loop
  user envelope, not a replay of individual source arrivals.

Numeric provenance is preserved. Its earlier Poisson-arrival prose is replaced
with a scope statement: delivered arrival statistics were not established by
these artifacts. Extraction metadata retains its original filter-version label;
the RetailRocket bot filter was unchanged between selection rules v1 and v2.
- `summary/headline.json`: canonical presentation input, generated by `verify.py`.
  Other summaries contain per-repetition inputs, exact paired tests and peaks.

Client p95 uses the Locust `Aggregated` row, including failures and the mixed `/`
and `/cpu` request population. Medians are across repetitions, not pooled request
percentiles. Exact two-sided Wilcoxon uses midranks for tied absolute differences
and removes zero differences. Tests are unadjusted; failure to detect a tuned/stock
difference does not establish equivalence. Arm order was not randomized.

Ready-pod hours integrate the left sample's ready count until the next sample.
Integration covers the retained sample span, with no extrapolation to the end of
the 18-minute window. This is ready-replica time, not consumed CPU-seconds or a
monetary quantity. Ratios use the unrounded medians. Using rounded displayed
medians produces slightly different last digits. Replica peaks use only samples
within each arm's inclusive `t0` through `t0 + 1080 seconds` window, including for
the contaminated file.

This minimal package does not include Prometheus CSVs or substantiate a coverage,
CPU-utilization, SLO, billing or cold-start distribution claim. The experimental
collector and its general analysis remain in the repository; v1.1 publication uses
this verifier and its exclusions instead of the general aggregator.

## Integrity and provenance

`MANIFEST.json` covers every file except itself and `SHA256SUMS`. `SHA256SUMS`
also covers the manifest. No recursive self-hash is claimed. Source hashes and
relative local source identifiers document curation; those private originals are
not required to verify this package. Hashes establish consistency, not independent
attestation of how the experiments were conducted.

Local curation can be repeated with `scripts/build_public_evidence.py` while its
private inputs exist. Summary regeneration and verification need only this bundle.
The public figures are generated separately by `scripts/generate_public_figures.py`
from these summaries.

From the repository root, `scripts/generate_publication_text.py` regenerates the
bounded findings blocks in README, RESULTS and Pages; `--check` rejects drift.
Neither presentation script is needed by the standalone evidence verifier.
